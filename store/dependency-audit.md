Backing detail for `privacy-declarations.md`. One row per runtime dependency in `package.json`, checked individually: what it's for, where (if anywhere) it's actually called from `src/`, and whether it has any network or data-collection capability that could make the "no data collected" declaration false.

## Dev-only dependencies (not shipped in the app binary)

`@testing-library/react-native`, `jest`, `jest-expo`, `react-test-renderer`, `typescript`, `@types/*` — none of these ship in the built app, so they have no bearing on what the running app does or the store's privacy questionnaires (which ask about the shipped binary's behavior).

## What would need to change this audit

Any of the following would require updating this file and re-checking `privacy-declarations.md`'s answers before the next release:

- A new dependency that makes an HTTP/WebSocket call of any kind.
- Calling `expo-notifications`' remote-push APIs (`getExpoPushTokenAsync`/`getDevicePushTokenAsync`) — currently unused, and doing so would register the device with Expo's or Apple/Google's push infrastructure, which is data leaving the device.
- Any analytics, crash-reporting, attribution, or ad SDK (all explicitly out of scope per spec §2/§9).
- Any change to `expo-sqlite`'s configuration toward a remote/replicated database mode.
