## Architecture decisions → `docs/adr/`

- **ADR-0001** — sessions keep momentum sacred: never manually resumable; auto-resume only within a 5-minute absence grace (resolves §14 Q1).
- **ADR-0002** — stems carry text + one optional category; no note/tag field (resolves §14 Q3).
- **ADR-0003** — endings rows are created on first keypress, not on submit; `endings.submitted_at` is nullable; `sessions.last_activity_at` added (deviates from the spec DDL and §6.3.4).
- **ADR-0004** — morning/evening sittings replace weighted stem draws and random notifications; two fixed daily local notifications; `notification_schedule`/`stems.weight` kept, vestigial.
- **ADR-0005** — official Sentence Completion programme adopted (Leigh Branden permission): seeds verbatim from the official list, weekly reflection + third notification, evening toggle at first launch, Android release includes it.
- **ADR-0006** — `docs/design/DESIGN.md` is a published view of `src/constants/theme.ts`; theme.ts stays normative, re-extract after any theme change; `npm run design:lint` gate.
- **ADR-0007** — practice composition = user picks + gated programme block; activation provenance retires week-set blanket automation; §13.7 handling of the two write-time columns + the upgrade-time limitation + the unlock-floor gray zone (packet 7 wave 2, D1–D4).
- **ADR-0008** — mockup-first design workflow: every design change ships an HTML mockup first, owner agreement gates any code; logic changes with a visual surface get an HTML mirror running the real pure functions over example data (owner-confirmed p7 debrief).

## Resolved open questions (§14)

1. **Session resumability** — never manually resumable → ADR-0001.
2. **On-demand stem repeat** — yes; library starts bypass the practice queue (`origin = 'manual'`).
3. **Per-stem note/tag** — no → ADR-0002.
4. **Review period** — default 7 days, selectable at review time from presets; `reviews` stores explicit `period_start`/`period_end`.

## Environment quirks

- `npm ci` must always carry `--legacy-peer-deps`: plain npm auto-installs peer dependencies the legacy resolution intentionally omits (measured 2026-09-23: react-native-gesture-handler, react-native-reanimated, react-dom and ~40 more; a strict lock would flip expo's native autolinking, so legacy stays).
- RESOLVED 2026-09-23: the old "expo-asset repeatedly vanishes" quirk was a lockfile hoisting defect — the lock held `expo-asset@57.0.16` only nested under `node_modules/expo/`, invisible to expo-font's root resolution (`expo-font/src/FontLoader.ts` imports it), so jest failed on every fresh install while the `--no-save` remedy masked it. The lock now hoists expo-asset to top level (same version, expo's declared range `~57.0.16`); `npm ci --legacy-peer-deps` installs it, jest needs no remedy. If it ever recurs, the lock lost its hoisted expo-asset entry again.
