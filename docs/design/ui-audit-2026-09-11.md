# UI audit — 2026-09-11

Code-level audit (no simulator). Scope: `src/app/*` (excl. `debug.tsx`), `src/components/*`, `src/constants/theme.ts`. Audited around two fixed, concurrently-landing changes: (a) write screen's save button labels itself with the countdown, green→red (`PressureColors`, already in theme.ts); (b) stems screen gets per-category chip colors + long-press active/inactive row tinting (`CategoryColors`, not yet in theme.ts).

## 1. Audit

**theme.ts** (`src/constants/theme.ts:9–68`). Two colors total per theme (`text`/`background`/two greys/`error`). No accent, no semantic success/warning, no elevation/border tokens, no radius scale (screens hand-roll `Spacing.two` as radius everywhere). `Spacing` scale exists and is well-used but has no name for "the number screens use as border radius" — it's borrowed from spacing, which is a latent naming smell once radius wants to diverge from spacing. `PressureColors` (`:40–43`) is deliberately theme-invariant — good precedent to follow for `CategoryColors`, which the brief requires "both themes, AA-checked," i.e. NOT theme-invariant like `PressureColors`; the two new palettes will have different contrast strategies and that's fine, but it means `CategoryColors` needs its own AA proof comment, not a copy of `PressureColors`'s.

**index.tsx** (`src/app/index.tsx`). `styles.primaryButton` (`:160–167`) and `styles.tile` (`:182–191`) both use flat `theme.backgroundElement` — primary CTA ("Start writing") is visually identical in weight to the six secondary nav tiles below it (`:114–124`), just bigger. No hierarchy signal beyond size; a first-time user has no color/weight cue that "Start writing" is the one action that matters. `SECONDARY_LINKS` grid (`:47–54`) renders 6 equal tiles with plain sans labels — Stems/History/Review/Settings/Export/Import read as an undifferentiated wall; this is the single highest-value spot for the owner's "use color" ask since it's the first screen every session starts from.

**write.tsx** (`src/app/write.tsx`). Core loop screen, currently the most restrained: no header chrome (`:134–148`, correct per §10), thin 3px progress track (`:287–291`), pressure-animated button (`:301–312`, the landing fixed change slots into `styles.button` cleanly — no structural conflict). One real gap: dimmed prior endings (`:172–176`) and the active input sit in the same vertical rhythm with no visual separator beyond opacity — on a long session (6 endings) the screen becomes a wall of grey-then-black serif text with no scan anchor. `styles.button` (`:301–306`) is shared textually between idle "Start", active "Next", and done "Close" — three different intents, one visual treatment; once "Next" becomes the countdown label, "Start"/"Close" will look inconsistent unless they're deliberately kept calm/static (they should be — only the countdown button needs urgency).

**stems.tsx** (`src/app/stems.tsx`). `StemRow` (`:141–182`) is a flat `backgroundElement` box; category is buried in a small secondary-text metadata line (`:164–166`, `[category, origin, status].join(' · ')`) — exactly what `CategoryColors` chips are meant to fix, but the row itself has no color slot reserved (no left border, no tint) for the long-press active/inactive toggle the brief describes — that's new surface, not a retrofit of an existing element. `FilterRow`/`FilterChip` reused 3× here (state/origin/category, `:93–123`) — one shared component, good. Category filter chips (`:116–123`) currently render category names as plain-selected/unselected grey chips; this is the direct target for `CategoryColors`.

**stem-edit.tsx** / **stem-import.tsx**. Category chosen via the same `FilterChip` row (`stem-edit.tsx:139–144`, `stem-import.tsx:84–89`) with a local hardcoded `CATEGORIES` array duplicated in both files (`stem-edit.tsx:15`, `stem-import.tsx:14`) — should both read from one shared constant once `CategoryColors` exists (theme.ts is the natural home, keyed the same way). Once stems.tsx has category colour, these two pickers showing categories in flat grey will look like a regression by omission.

**history.tsx**. Reuses `FilterRow`/`FilterChip` 3× (date/category/stem, `:101–133`) consistently with stems.tsx — good precedent for shared `FilterRow` extraction. `SessionRow`/`SearchResultRow` (`:166–215`) are flat cards identical in shape to stems.tsx's `StemRow` and export/import's `card` style — three near-identical "rounded box, `backgroundElement`, padding three, radius two" implementations with no shared `Card` primitive (`history.tsx:284–288`, `stems.tsx:257–264`, `export.tsx:81–85`).

**session-detail.tsx**, **review.tsx**. Same flat-card pattern (`session-detail.tsx:131–135`, `review.tsx` sessionBlock has no card at all — `:252–254`, just a `gap` — inconsistent with session-detail's boxed endings for structurally the same content: a stem + list of endings). Review's meta-stem sub-screen (`MetaStemSession`, `:176–228`) duplicates write.tsx's active-session layout (progress track, input, button) near verbatim with no shared component — a second maintenance surface for the same visual pattern, and will silently miss the countdown-button change landing in write.tsx unless someone remembers to port it.

**export.tsx**, **import.tsx**. Nearly identical screens (format cards with description + spinner) — good internal consistency, no complaint. Both entirely monochrome; fine for a low-frequency utility screen, but the three export format cards (`export.tsx:48–63`) are undifferentiated — a small accent per format (or an icon) would help scanning without violating restraint.

**settings.tsx**. Longest screen, all flat grey `ChipToggle`/`NumberStepper` rows with no visual grouping beyond `Spacing.four` gaps between `ThemedView style={styles.section}` blocks (`:264–297` etc.) — sections have no header rule, border, or background differentiation, so "Stem time limit" and "Notification timing" blocks blend into one long scroll. The destructive block (`:417–432`) is the only place color (`themeColor="error"`) is used at all outside the literal `error` swatch — correct restraint, but it means the entire settings screen currently has zero non-error color signal.

**onboarding.tsx**, **about-method.tsx**, **lock-screen.tsx**. Onboarding's step dots (`:219–229`) are the only "progress" indicator in the app besides the timer bar — two different progress idioms (dots vs. bar) for conceptually the same "how far through this flow" signal, worth noting though not urgent. About-method and lock-screen are minimal and fine as-is.

**Shared components**. Only two exist: `ThemedText` (5 `type`s, `themed-text.tsx:8`) and `ThemedView` (`themed-view.tsx`), plus `FilterChip` (`filter-chip.tsx`). No `Button`, `Card`, `SectionHeader`, or `EmptyState` component — every screen hand-rolls `Pressable` + `styles.button` (near-identical `paddingVertical: Spacing.three, paddingHorizontal: Spacing.four, borderRadius: Spacing.two` appears in write.tsx, stem-edit.tsx, stem-import.tsx, review.tsx×2, onboarding.tsx, lock-screen.tsx — at least 7 copies) and every list/detail screen hand-rolls its own "row/card" style. `EmptyState` text (`"No stems match."`, `"Nothing here yet."`, `"No matches."`, `"Nothing written in this period."`) is copy-consistent in tone but structurally four separate one-off `ThemedText` renders (stems.tsx:130–132, history.tsx:141–144/153–157, review.tsx:138–140) with no shared layout (e.g. no consistent vertical centering/padding when a list is empty).

**Cross-cutting**:

1. **No accent/semantic color system.** Every screen is `text`/`textSecondary`/`backgroundElement`/`backgroundSelected`/`error` — five values total govern the whole app. This is the literal thing the owner is asking to change.
2. **Radius and "card" are ad-hoc, not tokens.** `Spacing.two` (8) is reused as border radius everywhere by convention, never named as a radius scale; button/card/chip radii are never differentiated (a chip and a full-width primary button use the same 8px radius today).
3. **No `Card`/`Button`/`SectionHeader`/`EmptyState` components** — 7+ duplicated button styles, 4+ duplicated card styles, 4 duplicated empty-state renders, 2 duplicated `CATEGORIES` constants.
4. **No elevation/border vocabulary** — flat fills only; on a colorful redesign, cards and buttons will need a defined way to separate from background beyond fill color alone (hairline border token) especially in dark mode where `backgroundElement`/`backgroundSelected` are close in luminance.
5. **Type scale is complete but has no defined weight/tracking system beyond title/subtitle's `600`** — fine, not a defect, just noted as something the new tokens should preserve rather than expand unnecessarily.
6. **Accessibility is consistently good**: `accessibilityRole`/`Label`/`State` present on nearly every interactive element, `MinTouchTarget` applied correctly throughout, error text uses `themeColor="error"` (already AA-checked in theme.ts) with `accessibilityLiveRegion="polite"`. This is a strong foundation — the redesign must not regress it.

## 2. Design system proposal

All additions to `src/constants/theme.ts`; nothing here requires a library, everything is plain RN `View`/`Text` + `StyleSheet`.

**Spacing** — keep existing `Spacing` scale (half/one/two/three/four/five/six = 2/4/8/16/24/32/64) unchanged; it's already consistent and well-adopted. No change needed.

**Radius (new)** — name what's currently an implicit convention:

```ts
export const Radius = { chip: 999, small: 8, medium: 12, large: 20 } as const;
```

`chip` = pill (replaces `Spacing.three` used ad hoc for pill-ish chips); `small` = current de facto default (buttons, inputs); `medium` = cards; `large` = the primary CTA / sheets. Migrating existing `borderRadius: Spacing.two` call sites to `Radius.small` is a mechanical rename, not a visual change, in cycle 1.

**Type scale** — keep the 5 existing `ThemedText` types (default/title/subtitle/small/stem) and their sizes/weights/line-heights as-is (they're coherent: 16/24, 32/44/600, 20/30/600, 14/22, 22/34 serif). Add one new type, `eyebrow`, for section labels/category labels (12px/16, uppercase-ish via letterSpacing, sans, `textSecondary` by default) — the one gap: nothing today distinguishes "a label above a group" from "small secondary body text," and `SectionHeader` needs it.

**Semantic colors (extend `Colors.light`/`Colors.dark`)**:

```ts
accent: '#...',        // one warm brand hue, both themes, ≥4.5:1 on background
accentMuted: '#...',   // accent at low-opacity-equivalent fill for card backgrounds
border: '#...',        // hairline, ~10–15% opacity equivalent of text on background
success: '#...',       // reuse PressureColors.calm family if AA-safe on both bg's, else derive
```

`accent` is the one addition that does the heavy "warm, confident, colorful" lifting on Home's primary CTA and section headers — everything else (`CategoryColors`, `PressureColors`) is already scoped to specific screens. Keep `accent` to a single hue; do not add a second "brand" color — that's the fastest way back to a gamified rainbow.

**CategoryColors (already commissioned, landing concurrently)** — audit note only, not a spec here: when it lands, `stem-edit.tsx` and `stem-import.tsx`'s duplicated local `CATEGORIES` array should be replaced by iterating `Object.keys(CategoryColors.light)` (or a shared `CATEGORIES` export next to it) so the three category pickers in the app (stems filter, stem-edit, stem-import) can never drift out of sync with the palette.

**Shared components to extract** (`src/components/`):

- **`Card`** — `ThemedView` wrapper: `backgroundElement` fill, `Radius.medium`, `Spacing.three` padding, optional hairline `border` token. Replaces the 4+ duplicated row/card styles in stems/history/session-detail/export/import.
- **`Button`** — `Pressable` + `ThemedText` wrapper with `variant: 'primary' | 'secondary' | 'text'`. `primary` = `accent` fill, white label, `Radius.large`; `secondary` = current `backgroundElement` treatment (today's only style, becomes the "secondary" case); `text` = no fill, for Close/Cancel/Skip-style affordances. Replaces the 7+ duplicated `styles.button`.
- **`Chip`** — generalize existing `FilterChip` to accept an optional `color` prop (hex) for the selected-state fill/border, so `CategoryColors` chips and the existing grey filter chips share one component instead of stems.tsx growing a second chip implementation.
- **`SectionHeader`** — `eyebrow`-type label + optional trailing hint text, for Settings' section blocks and any grouped list.
- **`EmptyState`** — centered `ThemedText` (default + textSecondary) with consistent vertical padding, replacing the 4 one-off empty renders.

Everything above is implementable with `View`/`Text`/`Pressable`/`StyleSheet` — no new dependency required for the design system itself.

## 3. Cycle plan

**Cycle 1 — Design-system foundation.** Goal: land tokens + shared components with zero visible screen changes (additive only), so later cycles are pure adoption diffs. Files: `src/constants/theme.ts` (add `Radius`, `accent`/`accentMuted`/`border`/`success` semantic colors, `eyebrow` note for `ThemedText`); `src/components/themed-text.tsx` (add `eyebrow` type); `src/components/button.tsx` (new); `src/components/card.tsx` (new); `src/components/filter-chip.tsx` (extend with optional `color` prop, backward compatible); `src/components/section-header.tsx` (new); `src/components/empty-state.tsx` (new). Done-criteria: `npm run typecheck` and `npm test` pass unchanged; no screen file is modified; every new token/component has an AA-contrast comment matching the existing `PressureColors`/`error` comment style; `Button`'s `primary` variant measured ≥4.5:1 in both themes.

**Cycle 2 — Core loop (Home, Write, Stems, stem-edit, stem-import).** Goal: apply `Button`/`Card`/`Chip`/`Radius`/`accent` to the screens used every session, and land the two concurrent fixed changes (pressure-label button, `CategoryColors` chips + long-press toggle) inside this same pass since they touch the same files. Files: `src/app/index.tsx` (primary CTA → `Button variant="primary"`, secondary grid tiles → `Card` or `Button variant="secondary"`), `src/app/write.tsx` (adopt `Radius`, verify pressure-button change composes with `Button` or stays a bespoke `Animated.View` — bespoke is fine, don't force it into `Button`), `src/app/stems.tsx` (`StemRow` → `Card`, category chip → `Chip color={CategoryColors...}`, add long-press handler + row tint), `src/app/stem-edit.tsx`, `src/app/stem-import.tsx` (both: `Button`, `Chip` for category, dedupe `CATEGORIES` against `CategoryColors` keys). Done-criteria: Home's "Start writing" is visually the singular primary action on the screen; stems list shows a distinct color per category and a visible active/inactive tint on long-press; write.tsx's save button shows countdown text with the calm→urgent fade; `stem-edit`/`stem-import`'s category picker matches stems.tsx's palette exactly (same hex per category); no touch target regresses below 44; typecheck/tests pass.

**Cycle 3 — Library/history group (History, session-detail, Review).** Goal: adopt `Card`/`EmptyState`/`SectionHeader`, and de-duplicate Review's meta-stem sub-screen against Write's pattern where practical. Files: `src/app/history.tsx`, `src/app/session-detail.tsx`, `src/app/review.tsx`. Done-criteria: `SessionRow`, `SearchResultRow`, session-detail's ending rows, and review's session blocks all render via `Card` (visually consistent radius/fill/border across all three screens); all "nothing here" states use `EmptyState`; no new component introduced beyond what cycle 1 shipped.

**Cycle 4 — Settings/export/import/misc polish.** Goal: visually group Settings via `SectionHeader`, apply `Card`/`Button` to Export/Import, leave About/Onboarding/Lock untouched unless trivial. Files: `src/app/settings.tsx`, `src/app/export.tsx`, `src/app/import.tsx`. Done-criteria: Settings' existing section blocks each have a visible `SectionHeader` label (not just a `small`/`textSecondary` line); Export's three format cards and Import's two mode cards use `Card`/`Button`; destructive "Delete all data" retains its current two-step confirm and `error` color, unchanged in behavior; typecheck/tests/lint all pass; a final pass confirms no screen introduced an evaluative or gamified visual (no badges, no streak emphasis, no score-like numerals beyond the existing descriptive counts).

---

Total scope target: cycle 1 is the biggest (foundation), cycles 2–4 are mechanical adoption of the same primitives screen-group by screen-group — realistic for ~90 minutes if cycle 1 stays additive-only and later cycles resist inventing new patterns.
